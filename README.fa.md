# راهنمای فارسی ClubSphere — Next.js

نسخهٔ SPA با App Router و جابه‌جایی بین صفحات بدون رفرش کامل؛ بدون بک‌اند، دیتابیس یا API خارجی. تصاویر واقعی و قابلیت‌های نسخهٔ قبلی حفظ شده‌اند.

## اجرا روی سیستم

Node.js نسخهٔ ۲۲ یا بالاتر نصب کنید، پوشهٔ پروژه را در ترمینال باز کنید و اجرا کنید:

```bash
npm ci --include=dev
npm run dev
```

آدرس توسعه: http://localhost:3000

برای ساخت و بررسی خروجی نهایی:

```bash
npm run build
npm run check
npm run preview
```

خروجی نهایی در پوشهٔ `out` است. برای این پروژه `next start` استفاده نکنید.

## انتشار روی GitHub Pages

۱. یک مخزن مثل `clubsphere` بسازید.

۲. محتویات داخل پوشهٔ پروژه را در ریشهٔ مخزن قرار دهید؛ فایل `package.json` باید مستقیماً در ریشه باشد. پوشهٔ مخفی `.github` و فایل `package-lock.json` را هم منتقل کنید.

۳. در Settings → Pages، گزینهٔ Source را روی **GitHub Actions** بگذارید.

۴. تغییرات را روی شاخهٔ `main` push کنید یا از بخش Actions، workflow را دستی اجرا کنید.

۵. پس از موفقیت build و deploy، سایت در آدرسی مثل `https://USERNAME.github.io/clubsphere/` قرار می‌گیرد.

نام مخزن و پیشوند مسیر به‌صورت خودکار از تنظیمات Pages گرفته می‌شود. نیازی به تغییر دستی لینک عکس‌ها یا ساخت شاخهٔ gh-pages نیست. این بسته هنوز به حساب GitHub شما منتشر نشده است.

## تغییر محتوا

- اطلاعات بازیکنان، اسطوره‌ها، اخبار و مسابقات: `public/data`
- متن و ساختار صفحات: `scripts/content.mjs`
- ظاهر و رنگ‌ها: `public/assets/style.css` و `tailwind.config.cjs`
- تعامل‌ها: `public/js`

پس از تغییر JSON یا قالب‌ها، `npm run prepare:pages` را اجرا کنید. فایل‌های JSX صفحات از این منابع تولید می‌شوند و نباید مستقیماً ویرایش شوند. جزئیات معماری، دامنهٔ اختصاصی، اجرای زیرمسیر و محدودیت‌ها در README انگلیسی آمده است.

این پروژه غیررسمی است. تصاویر رسمی و لوگوها مشمول مجوز کد پروژه نیستند؛ منابع و حقوق صاحبان اثر در `ASSET-CREDITS.md` ثبت شده‌اند. نتایج و برنامهٔ مسابقات همچنان دادهٔ نمایشی هستند.

## اصلاح نسخهٔ ۲.۱

تمام لینک‌های داخلی از Next Link استفاده می‌کنند. هنگام تغییر مسیر، رویدادها، تایمرها، observerها و درخواست‌های معلق صفحهٔ قبلی پاک می‌شوند و تعامل‌های صفحهٔ جدید دوباره فعال می‌شوند. خروجی export صرفاً برای میزبانی بدون سرور روی GitHub Pages باقی مانده و به معنی رفرش کامل صفحات نیست. برای اجرای توسعه نیز به بک‌اند جداگانه نیازی نیست.

## اصلاح اسکرول در نسخهٔ ۲.۱.۱

ورود با لینک داخلی به مسیر جدید از بالای صفحه انجام می‌شود. لینک‌های بخش‌های داخل صفحه حفظ شده‌اند و بازگشت مرورگر به مدیریت تاریخچه سپرده می‌شود. فایل‌های AppLink و NavigationScroll مدیریت اسکرول را انجام می‌دهند.
